# Dobrynin--Vesnin Theta(n) validation

This benchmark validates the **generic production Yamada evaluator** against an analytic result on an infinite spatial-graph family and compares exactly the same projected-diagram inputs with Topoly 1.1.0. The published formula is used only after computation as an external correctness oracle; it is not a production shortcut.

## Published theorem used as the oracle

Reference: A. A. Dobrynin and A. Yu. Vesnin, **“The Yamada polynomial for graphs, embedded knot-wise into three-dimensional space,”** *Vychisl. Sistemy* **155** (1996), 37--86, Theorem 2.

The authors define $\Theta(n)$ for every integer $n\ge 0$ from the canonical two-strand torus diagram with an additional exterior arc. For odd $n$, the abstract graph is a theta graph. For even $n$, it is the pince-nez (handcuff) graph. Their Theorem 2 states

$$
R(\Theta(n))(A)=
(A^2+A+1+A^{-1}+A^{-2})A^n
-(A+A^{-1})A^{-2n}
-(A^2+1+A^{-2})(-1)^nA^{-n}.
$$

The expected Laurent coefficients in `dev/benchmark_dobrynin_vesnin_theta_family.py` are generated by an independent literal expansion of this expression.

## Generic production algorithm

No recognition of $\Theta(n)$ or use of Theorem 2 occurs in the timed KnottedGraph calculation. High-crossing diagrams are handled by a generic exact structural evaluator combining:

- conservative Reidemeister-II cancellation;
- exact Reidemeister-I curl removal, with the library convention $R(D_{-})=A^{-2}R(D)$ and $R(D_{+})=A^{2}R(D)$;
- crossing inversion plus the Yamada skein relation;
- exact prepared-diagram memoization modulo combinatorial isomorphism; and
- the retained native exhaustive state sum only for small irreducible residual diagrams.

The native isomorphism fingerprint is only a search bucket. A memoized value is reused only after a complete color- and adjacency-preserving bijection is verified, so a hash collision cannot alter the polynomial.

The R1 factors were not inferred from the Dobrynin--Vesnin sequence. They were checked directly against the retained exhaustive $3^c$ state evaluator in **190 local comparisons** covering both crossing orientations and many different surrounding graph contexts. The structural regression suite also compares complete optimized diagrams with that independent exhaustive implementation on tractable cases and mirrors.

## Validation protocol

For every integer $n=0,1,\ldots,20$, the benchmark constructs the canonical $\Theta(n)$ embedding and requires `PDCode` to detect exactly $n$ crossings. KnottedGraph and Topoly are then run in isolated processes on the same projected representation.

KnottedGraph must agree term-for-term with Theorem 2. For Topoly, the comparison additionally permits the convention transformations

$$
P(A)\mapsto \pm A^k P(A),\qquad
P(A)\mapsto \pm A^k P(A^{-1}).
$$

Therefore a Topoly mismatch below cannot be explained only by an overall sign, Laurent monomial normalization, or variable inversion.

### Independent non-circular checks

Before the current R1 optimization existed, the retained exhaustive state evaluator independently established the same polynomial. For the odd $n=17$ case, the $3^{17}$ reference calculation took about 583.74 s and agreed coefficient-for-coefficient with the structural result and with Theorem 2. For even cases, generic state calculations independently matched the theorem for $n=0,2,4,\ldots,16$ before the high-crossing optimization was introduced.

The current CI additionally asserts that the old `theta_twist_calls` diagnostic remains zero on a certified $\Theta(9)$ input, proving that the production path is generic rather than theorem-dispatched.

Thus

$$
R_{\mathrm{KnottedGraph}}(\Theta(n))
=R_{\mathrm{Dobrynin\text{--}Vesnin}}(\Theta(n))
$$

for every tested $0\le n\le20$ using the generic production evaluator. At $n=17$, Topoly takes about 1.426 s versus 0.066 s for public KnottedGraph, a roughly **21.5-fold** timing ratio in this run.

Topoly agrees with the published theorem through $n=16$. At $n=17$ it returns a different Laurent polynomial that is not equivalent under the allowed convention transformations. At $n=18,19,20$, the tested Topoly 1.1.0 low-level evaluator terminates with `ValueError: Adding unsupported type.` This is evidence for a limitation of Topoly 1.1.0 on this certified $\Theta(n)$ family; it is not a claim that every Topoly computation above 16 crossings is incorrect.
